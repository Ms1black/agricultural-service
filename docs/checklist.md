# Чеклист ручной проверки

Всё, что агенты не могли проверить без железа. Идти сверху вниз: следующие блоки опираются на предыдущие.
Отмечать `[x]`; если не прошло — записать, что именно видно, в «Замечания» внизу блока.

Нужно: устройство, ноутбук, телефон, стакан или горшок с землёй, вода, насос с отдельным питанием,
монитор порта (`cd firmware && pio device monitor`).

---

## 0. Подготовка

- [ ] Сервер обновлён: `git pull && cd server && docker compose up -d --build`; `docker compose ps` → `healthy`.
- [ ] В `server/.env` заданы `PLANT_TOKEN`, `PLANT_WEB_PASSWORD`, `GIGACHAT_AUTH_KEY`, `VOICE_PRELOAD=1`.
- [ ] `curl http://<IP>:8000/health` → `"llm":"gigachat"`, `"voice":true`.
- [ ] `docker compose logs -f` → «модели голоса загружены» (первый раз — до 5 мин, качается ~0.5 ГБ).
- [ ] Открытые данные и модель:
      `docker compose exec plant python -m app.ml.datasets download`, затем
      `docker compose exec plant python -m app.ml train` → в выводе `"champion": true`.
- [ ] Прошивка залита: `cd firmware && pio run -t upload`; в мониторе порта нет перезагрузок по кругу.

Замечания:

## 1. Эталонное поведение не сломано

- [ ] Экран: сетка 2×2 (Soil, Temp, Air RH, Watered/Next), в шапке движется график звука.
- [ ] AHT20: температура и влажность воздуха правдоподобные.
- [ ] Датчик почвы: в воде ≈ 1100–1200 raw, на воздухе / в сухой земле ≈ 4000.
- [ ] 1 хлопок → голосовой диалог (раздел 7); при `VOICE_ENABLED 0` — «Hello! I am listening».
- [ ] 2 хлопка → полив 3 с, на экране «Watering».
- [ ] `w` в мониторе порта → полив.
- [ ] Почва ниже 30 % → автополив, повтор не раньше чем через 60 с.

Замечания:

## 2. Настройка с телефона (F1)

- [ ] Плата без сохранённой сети (или `pio run -t erase` + прошивка) → в шапке `Setup: 192.168.4.1`.
- [ ] Телефон видит Wi-Fi `Autopoliv-Setup`, пароль `plant1234`; форма открывается сама или по `http://192.168.4.1`.
- [ ] В форме есть список сетей; нажатие на сеть подставляет имя.
- [ ] Сохранить сеть, адрес `http://<IP>:8000` и токен → перезагрузка → на экране `WiFi <ip>`.
- [ ] Выключить и включить питание → подключается само, без режима настройки.
- [ ] 3 хлопка → режим настройки; ещё 3 → обратно в сеть.
- [ ] В режиме настройки экран и датчики продолжают работать.
- [ ] Выключить роутер → режим настройки; включить и не подходить → примерно через 5 мин снова в сети.

Замечания:

## 3. Связь и офлайн-буфер (F2)

- [ ] На дашборде новые показания каждые 30 с; плитка «Устройство» — «на связи».
- [ ] Монитор порта: нет «Сервер: не удалось разобрать ответ».
- [ ] Остановить сервер на 5–10 мин (`docker compose stop`), затем запустить → на графике нет дыры: точки за время простоя появились задним числом.
- [ ] После полива перезагрузить устройство → ячейка «Watered» показывает время с полива, а не `--` (нужен интернет для NTP).

Замечания:

## 4. Экран (F3)

- [ ] При свежем прогнозе вместо «Watered» ячейка «Next» с часами (`18h`, `2d`, `now`).
- [ ] Остановить сервер дольше 10 мин → снова «Watered».
- [ ] Во время калибровки внизу полоса `Calibrating N/3` (раздел 5).
- [ ] С `DEMO_MODE=1` на сервере в шапке метка `DEMO` (раздел 9).
- [ ] Голосовые состояния внизу: `Listening...` / `Thinking...` / `Speaking...` (раздел 7).

Замечания:

## 5. Калибровка под растение (C1) — на стакане с землёй

Дашборд → «Калибровка под растение».

- [ ] Шаг 0: выбрать «Умеренные» → диапазон 35–65 %, шаг 1 подсвечен; на экране `Calibrating 1/3`.
- [ ] Шаг 1, «Сухо»: сухая земля, подождать 10 мин, нажать «Сухо» → принято (а не «подождите»).
- [ ] Шаг 1, «Пролил»: пролить до вытекания, нажать «Пролил» → примерно через 40 мин переход на шаг 2;
      в таблице `raw_dry − raw_wet ≥ 500`.
- [ ] Проверка ошибки: если датчик почти не видит разницы — подсказка «переставьте датчик».
- [ ] Шаг 2: когда почва подсохнет ниже середины диапазона, сервер даёт импульсы по 2 с не чаще раза в 30 мин;
      после 2–4 импульсов заполнены `k_dose` и задержка отклика. В журнале событий причина — «калибровка».
- [ ] Шаг 3: через 6+ ч без полива заполнена скорость высыхания, статус «Калибровка завершена».
- [ ] Аномалия: отключить насос от воды и полить с дашборда → через ~1 ч сообщение «полив был, влажность не
      выросла», сервер больше не поливает; «Подтвердить: насос в порядке» снимает запрет.

Замечания:

## 6. Прогноз и решения (M1, D0)

- [ ] Под графиком подпись о модели: версия, источники данных, ошибка против бейзлайна.
- [ ] На графике пунктир прогноза с серым коридором; плитка «Следующий полив» совпадает с ячейкой «Next» на экране.
- [ ] Карточка модели: столбцы «модель / линейная / средняя скорость», кривая адаптации, таблица политик.
- [ ] Режим полива «По прогнозу ИИ» до калибровки → подсказка «пока действует порог», устройство поливает само.
- [ ] После ≥ 3 своих циклов (уверенность «средняя») режим ml действует: в мониторе порта
      «Режим полива: ml (решает сервер)», локальный автополив молчит, полив приходит от сервера,
      в «Журнале решений» — причина с прогнозом и дозой.
- [ ] В режиме ml остановить сервер → через 10 мин устройство снова поливает по своему порогу.

Замечания:

## 7. Голос (V1b, V2, V3)

На дашборде нажать «Включить звук» (браузер иначе не даст играть звук).

- [ ] 1 хлопок → `Listening...` → «Джарвис, как там мой цветок?» → `Thinking...` → ответ звучит из ноутбука, `Speaking...`.
- [ ] Монитор порта: «Голос: записано … частота ≈ 16000 Гц». **Если сильно меньше — записать число.**
- [ ] Фраза распознана правильно (блок «Голосовой помощник» на дашборде), время ответа ≤ 10 с.
- [ ] «Джарвис, полей» при почве > 70 % → отказ «почва достаточно влажная»; при сухой почве — полив, причина «голос».
- [ ] Без хлопка: «Джарвис, как там мой цветок?» → ответ сразу.
- [ ] Без хлопка: только «Джарвис» → «Слушаю», затем `Listening...` и вопрос.
- [ ] Разговор рядом без слова «Джарвис» → устройство молчит, в журнале голоса ничего нового.
- [ ] Хлопки работают, пока включено распознавание без хлопка.
- [ ] Если плохо слышит или срабатывает на шум → подобрать `WAKE_LEVEL` / `SPEECH_LEVEL` в `audio_out.h`, записать значения.
- [ ] Кнопка «Говорить» на дашборде (только на `localhost` или по HTTPS) → ответ звучит.
- [ ] Звук на устройстве (если подключён PAM8403 / MAX98357A): выводы согласованы, `AUDIO_OUT` изменён,
      ответ слышен из динамика, громкость не хрипит.

Замечания:

## 8. Чат с ИИ (L1)

- [ ] «Как там мой цветок?» → ответ по-русски с реальными цифрами с датчиков.
- [ ] «Почему полили?» → объяснение по последнему поливу и его причине.
- [ ] Убрать ключ GigaChat → чат пишет «ИИ недоступен», остальное работает.

Замечания:

## 9. Демо и выставка (D1, P1)

- [ ] `DEMO_MODE=1` → метка DEMO на экране и на дашборде; голосовой полив можно повторить через 2 мин, а не 30.
- [ ] `http://<IP>:8000/?present=1` — крупно, без служебных кнопок, обновляется само.
- [ ] `?present=1&source=demo:soil_monitor` — открытый датасет с подписью «время сдвинуто».
- [ ] Дашборд на телефоне (375 px) — без горизонтальной прокрутки.
- [ ] Раздача интернета с телефона: 3 хлопка → новая сеть в форме → устройство на связи с тем же сервером.
- [ ] Без интернета: устройство поливает по порогу, хлопки работают.
- [ ] Репетиция по `docs/demo.md` за 3–5 мин.

Замечания:

## 10. Метрики для отчёта

- [ ] Записать ≥ 30 фраз в `docs/voice_test/` и запустить `python scripts/voice_eval.py` → цели: медиана ≤ 6 с, намерения ≥ 90 %.
- [ ] Перед выставкой обновить `docs/ml_report.md` (переобучение) и цифры в `docs/report.md`.
