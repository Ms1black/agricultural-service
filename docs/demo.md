# Демонстрация: стенд и видео (D1, P1)

В видео и на стенде показываем только то, что работает. Источники данных называем честно:
модель обучена на открытых датасетах ([datasets.md](datasets.md)), метрики — [ml_report.md](ml_report.md).

## Подготовка

1. Сервер: `git pull && cd server && docker compose up -d --build`. В `server/.env`:
   `GIGACHAT_AUTH_KEY` (чат и голос), `VOICE_PRELOAD=1`; для записи — `DEMO_MODE=1`
   (интервал между поливами сервера 2 мин вместо 30, на экране и в вебе метка **DEMO**;
   10 с, 70 % и 6 поливов в сутки — без изменений).
2. Модель: `docker compose exec plant python -m app.ml.datasets download`, затем
   `docker compose exec plant python -m app.ml train`.
3. Устройство: прошить, настроить с телефона (3 хлопка → `Autopoliv-Setup`).
4. Дашборд для записи экрана: `http://<IP>:8000/?present=1` — крупно, без служебных кнопок.
   Открытый датасет как источник: `?present=1&source=demo:soil_monitor`.
5. Звук ответов — «Включить звук» на дашборде (браузер требует нажатия).
6. Стенд: горшок или стакан с землёй, датчик, насос с отдельным питанием, ёмкость с водой, полотенце.

## Стенд, 3–5 минут

| Шаг | Что делаем | Что видно |
|---|---|---|
| 1 | Рассказ: проблема полива, «каждый горшок сохнет по-своему» | дашборд: плитки, график за 7 дней |
| 2 | Показываем устройство | экран: Soil, Temp, Air RH, **Next** — через сколько часов полив |
| 3 | Карточка модели | «модель против бейзлайнов», кривая адаптации, сравнение политик |
| 4 | Хлопок, «Джарвис, как там мой цветок?» | `Listening... → Thinking... → Speaking...`, ответ из ноутбука |
| 5 | «Джарвис, полей», когда почва влажная | отказ: «почва достаточно влажная» — голос не обходит безопасность |
| 6 | Почва сухая → ячейка Soil чёрная → полив (2 хлопка или «Полить») | влажность на графике растёт, отметка полива с причиной |
| 7 | «Почему полили?» в чате | ИИ объясняет по журналу решений и событий |
| 8 | Без интернета | устройство поливает само по порогу (резерв) |

Запасной план без интернета: локальный автополив по порогу и хлопки работают без сервера.

## Видео, 2–3 минуты (P1)

| Время | Сцена | Можно снимать |
|---|---|---|
| 0:00–0:12 | Проблема: сухая земля, «универсальный полив не работает» | сразу |
| 0:12–0:30 | Устройство крупным планом: датчики, экран, насос | сразу |
| 0:30–0:42 | Настройка с телефона (можно вырезать) | сразу |
| 0:42–1:05 | Калибровка под горшок: мастер на дашборде, `Calibrating N/3` на экране | после C1 на реальном горшке |
| 1:05–1:35 | Ключевая: сухо → Soil чёрная → полив → влажность растёт (экран + дашборд рядом) | сразу |
| 1:35–2:05 | ИИ-прогноз: линия прогноза, метрики против бейзлайна, адаптация, политики | сразу (данные — открытые датасеты, подписать) |
| 2:05–2:35 | Голос: хлопок → вопрос → ответ; «полей» при влажной почве → отказ | после ручной проверки V2 |
| 2:35–2:55 | Архитектура и развитие (слайд) | сразу |
| 2:55–3:00 | Финал: растение, всё в норме | сразу |

Советы: экран ST7735S снимать телефоном со штатива в макрорежиме, без бликов; дашборд — OBS 1080p;
разделённый экран собрать при монтаже; закадровый текст — отдельно в тихой комнате.
Высыхание длится часами: таймлапс с подписью «ускорено ×N» или запись в `DEMO_MODE` с меткой DEMO.

## Ключевые числа для слайдов

Брать из `docs/ml_report.md` последней версии (не округлять в лучшую сторону):
ошибка времени до порога модели против линейного бейзлайна, кривая адаптации (0 → 5 своих циклов),
сравнение политик threshold / ml (поливов, средняя влажность, часы пересыхания).
