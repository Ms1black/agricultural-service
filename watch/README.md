# «Мой цветок» для Apple Watch

SwiftUI-приложение для **watchOS 26+** (в том числе Series 11 42 мм). Самостоятельно
читает существующий API FastAPI; приложение-компаньон для iPhone не требуется.
Порог watchOS 26 выбран для поддержки HTTP по IP через `NSAllowsLocalNetworking`.

Главная страница в стиле сайта: влажность почвы, температура дома, влажность воздуха,
последний полив, прогноз сервера и пиксельный Джарвис. Он моргает раз в 4,2 с и слегка
покачивается. При уменьшении движения, в Always On и неактивном приложении анимация остановлена.
Все карточки доступны прокруткой; свайп влево открывает настройки подключения.

## Однократная настройка сервера

При первом запуске открывается страница **«Подключение»**.

1. Адрес-шаблон: **`http://10.0.0.20:8000`**. Это пример, а не проверенный сервер.
   Укажи фактический адрес веб-дашборда, включая порт. `8000` — порт nginx в текущем Docker Compose.
   Используй корневой адрес без `/#overview`, query-параметров, логина и пароля в URL.
2. Введи **логин и пароль от сайта** (`PLANT_WEB_USER` / `PLANT_WEB_PASSWORD`).
   Предложенный логин — `admin`. Токен ESP32 (`PLANT_TOKEN`) для этих API не подходит.
3. Поле растения можно оставить пустым. Нажми **«Подключить и сохранить»**:
   приложение получает `/web/api/devices` и автоматически выбирает единственное растение.
   Если их несколько — выбери нужное в появившемся списке и нажми кнопку ещё раз.
4. После успешного чтения данных настройки сохраняются в **Keychain** только на этих часах,
   доступны при разблокировке и не попадают в исходники или UserDefaults.
   Нажми **«Показать данные»** или вернись свайпом к первой странице.
5. В дальнейшем приложение загружает данные автоматически при открытии и примерно каждые
   30 секунд, пока активно. При сворачивании запросы отменяются. После возврата или восстановления
   сети подключение повторяется; пересборка и повторный ввод пароля не нужны.

Как у контроллера, адрес и доступ задаются один раз и сохраняются. Автоматического поиска
произвольного сервера в сети нет. Часы не создают точку `Autopoliv-Setup` и не считывают секреты ESP32.
Wi-Fi управляется настройками самих Apple Watch. `10.0.0.20` — частный адрес: для доступа нужна
домашняя сеть или VPN с маршрутом к ней; мобильная сеть сама по себе доступа к этому IP не даёт.

Поддерживаются HTTPS и HTTP по IP/локальному имени. HTTP передаёт Basic-пароль без шифрования;
это явно показано перед подключением. Для публичного DNS-имени требуется HTTPS.
Глобальный `NSAllowsArbitraryLoads` не включён, проверка TLS-сертификата не отключается.
HTTP-редиректы не выполняются, чтобы не передавать пароль другому адресу: указывай конечный URL.

**«Забыть подключение»** после подтверждения удаляет сохранённые настройки и пароль из Keychain.
При редактировании адреса старое подключение остаётся сохранённым до успешной проверки нового.

## Данные и поведение при ошибках

- Используются существующие `/web/api/devices`, `/web/api/state`, `/web/api/forecast` и
  `/web/api/waterings` с HTTP Basic. Контракты и бэкенд не менялись.
- `soil_ok = 0` или отсутствующий датчик → «Нет данных» вместо вымышленного процента.
- Свежесть проверяется по времени сервера: замер старше 2 минут помечается как устаревший.
  Давность увеличивается и без успешных запросов; разница часов сервера и Apple Watch учтена.
- При потере сети последние значения остаются в памяти с явной отметкой «Нет связи · последние данные».
  После полного перезапуска без сети значения не восстанавливаются. Демоданные автоматически не подставляются.
- Без готового прогноза или при старых данных → «Прогноз недоступен». Ошибка прогноза не прячет датчики.
- Последний полив берётся из событий. Если среди последних 20 событий его нет, читается история
  поливов до 10 лет (максимальный период существующего API). Пустая история → «Нет записи»,
  ошибка её чтения → «История недоступна». В очередь полива записан ещё не выполненный полив —
  это состояние Джарвиса, а не новый момент последнего полива.
- `DEMO_MODE` на сервере отмечается меткой «ДЕМО»; его реальные данные не смешиваются с локальной демонстрацией.
- Клиент **только читает** сервер. Реальных команд насосу и голосового чата здесь пока нет;
  реплика Джарвиса формируется из состояния датчиков. Лимиты полива не меняются.

## Автономное демо

В настройках нажми **«Показать демо»** — доступно без сервера и пароля.
Явная метка «ДЕМО», вымышленные показания 46%, 24,0 °C, 55%, полив 2 ч назад.
Третья страница — выбор сценария и имитация полива (двойной свайп влево от обзора).
Подтверждение меняет пример на 58% и «Только что», затем время обновляется раз в минуту.
Сухой сценарий: 26%, полив 8 ч назад. Прогноз демо — линейный пример 2%/ч до 30%, не ML.
Возврат к реальному серверу: настройки → «Показать данные».

## Запуск на своих часах

1. Открой `watch/PlantWatch.xcodeproj` в Xcode. Если предложена установка компонентов watchOS,
   дождись её завершения. Версия Xcode должна поддерживать watchOS на твоих часах.
2. В **Xcode → Settings → Apple Accounts** добавь свой Apple Account самостоятельно.
   Пароль и коды подтверждения вводятся только в интерфейсе Apple.
3. В проекте выбери **TARGETS → PlantWatch → Signing & Capabilities**:
   оставь **Automatically manage signing**, выбери свою **Team**.
   Замени `org.autopoliv.PlantWatch` на уникальный Bundle Identifier, например
   `com.<твой-идентификатор>.PlantWatch`. Аккаунт и Team в исходники не включены.
4. Подключи спаренный с часами iPhone к Mac, подтверди доверие. Включи Wi-Fi и Bluetooth.
   Открой **Window → Devices and Simulators** и выполни подсказки Xcode для подключения часов.
5. На Apple Watch включи **Настройки → Конфиденциальность и безопасность → Режим разработчика**,
   перезагрузи часы и подтверди включение. Если пункта нет, сначала начни подключение через Xcode.
   Если Xcode попросит включить Developer Mode также на iPhone, выполни его подсказки.
6. В верхней панели Xcode выбери схему **PlantWatch**, устройством запуска — свои
   **Apple Watch Series 11**, затем нажми **Run (⌘R)**. Часы должны быть разблокированы.

Бесплатной **Personal Team** достаточно для личного тестирования. Подпись действует
7 дней, после чего приложение нужно заново собрать и установить через Xcode.
Публиковать приложение в App Store для этого не требуется.

Если часы не появились, проверь их подключение в Devices and Simulators и совместимость
версии Xcode с установленной watchOS. Для симулятора выбери установленный Apple Watch simulator;
при необходимости добавь watchOS runtime в настройках компонентов Xcode.

## Проверки

Из корня репозитория, установленный Xcode с watchOS SDK 26 или новее:

```sh
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer \
xcrun swift test --package-path watch --scratch-path /tmp/plant-watch-tests

DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer \
xcodebuild -project watch/PlantWatch.xcodeproj -scheme PlantWatch \
  -configuration Debug -sdk watchos -destination 'generic/platform=watchOS' \
  -derivedDataPath /tmp/plant-watch-build CODE_SIGNING_ALLOWED=NO build
```

Тесты API-клиента используют `URLProtocol` с подставными ответами, не обращаются к серверу
и не используют настоящие пароли. Проверяют Basic Auth, параметры устройства, числовые и булевы
флаги SQLite, пропущенные датчики, ошибку входа, недоступный прогноз, историю полива,
свежесть по серверным часам и запрет редиректов. CI запускает тесты и собирает watchOS Release.
Сборка без подписи проверяет код; для установки на часы нужна собственная Team в Xcode.

## Ручная проверка

1. Настоящий сервер доступен часам; в настройках введён его адрес, а не шаблон. Неверный пароль
   даёт понятную ошибку, не сохраняется и не подменяется демонстрационными значениями.
2. Единственное растение выбирается само; при нескольких запрашивается выбор.
   Показания и последний полив совпадают с веб-дашбордом для того же устройства.
3. После закрытия/открытия приложения разблокированные часы подключаются без повторного ввода пароля.
4. Отключи сеть: последняя карточка помечена как данные без связи; через 2 минуты замер устаревший.
   Верни сеть: данные обновляются. В Always On запросы/анимация остановлены, после пробуждения возобновляются.
5. Нет телеметрии / неисправный датчик / нет модели: пустые поля и сообщения, никаких случайных чисел.
6. После реального полива через существующий веб-интерфейс и события ESP32 на часах обновляется
   последний полив. Само появление команды в очереди не считается выполненным поливом.
7. На Series 11 42 мм карточки доступны прокруткой и при увеличенном шрифте, оба глаза моргают;
   при уменьшении движения персонаж неподвижен.
8. Демо работает без сети. Отмена имитации ничего не меняет; подтверждение → 58% и «Только что»;
   через минуту → «1 мин назад». Насос не включается.
9. «Забыть подключение» удаляет доступ; следующий запуск снова предлагает настройки.
