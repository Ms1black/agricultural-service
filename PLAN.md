# План реализации: ПАК ухода за комнатными растениями с применением ИИ

Документ для разработчиков и ИИ-агентов (Claude Code, Codex). Описывает, что уже есть,
что нужно сделать до выставки, в каком порядке и как проверять результат.

> **Агентам:** у вас нет доступа к устройству. Всё, что требует проверки на железе, проверяет
> человек. В каждом PR — раздел «Ручная проверка» с пошаговой инструкцией.

---

## 0. Ключевые решения и ограничения

| Вопрос | Решение |
|---|---|
| Срок | **меньше месяца** до выставки → приоритет — работающая демонстрация, а не полнота |
| Секция | ИИ и машинное обучение (+ устройство) |
| Обязательно на выставке | ML-прогноз полива, голосовой помощник «Джарвис», чат с ИИ о растении, реальный насос и динамик |
| Сервер | облачный Linux-сервер с Docker, **только IP, без домена** |
| Языковая модель | **GigaChat** (бесплатный Freemium для физлиц) + переключение провайдера настройкой (DeepSeek, YandexGPT — через OpenAI-совместимый API) |
| Распознавание речи | на сервере, бесплатно: **faster-whisper** (русский) |
| Синтез речи | на сервере, бесплатно: **Silero TTS** (русский) |
| Активация голосом | этап 1 — **по хлопку**; этап 2 (если успеваем) — слово **«Hey Jarvis»** через openWakeWord на сервере |
| Интернет на выставке | раздача с телефона |
| Работа агентов | GitHub, каждый агент в своей ветке, PR, слияние — человеком |
| Железо | в плане не расписывается; отмечены только зависимости от него |

Требования к серверу: Linux, Docker, **≥ 4 ГБ RAM** (faster-whisper + Silero), 2 vCPU.

## 1. Что уже есть

### Прошивка `firmware/autopoliv_ui/autopoliv_ui.ino` — **эталонная рабочая версия**

Проверена на устройстве. Любые изменения обязаны сохранять её поведение.
Рефакторинг — маленькими шагами с ручной проверкой после каждого.

Умеет:
- AHT20 — температура и влажность воздуха;
- датчик почвы: аналоговый A0 (медиана 31 замера, проверка разброса) + цифровой D0 как запасной;
- микрофон MAX9814: распознавание хлопков в отдельной FreeRTOS-задаче на ядре 0
  (1 хлопок — приветствие, 2 — полив);
- автополив по порогу 30 % с паузой 60 с;
- дисплей ST7735S (LovyanGFX): e-paper-стиль, сетка 2×2, в шапке — сглаженный график звука;
- Wi-Fi, телеметрия каждые 30 с, события (полив, загрузка), калибровка и команда полива из ответа сервера;
- ручной полив: `w` в мониторе порта.

Ограничения:
- Wi-Fi и адрес сервера — **константы в коде** (`WIFI_SSID`, `WIFI_PASS`, `SERVER`, `API_TOKEN`);
- ответ сервера разбирается **поиском подстрок**, не JSON-парсером;
- нет звука и записи речи.

### Сервис `server/server.py` (FastAPI + SQLite)

Приём телеметрии и событий, калибровка, ручной полив, веб-страница, выгрузка CSV.
Есть `Dockerfile` и `docker-compose.yml` (сборка образа не проверялась).

### Проверено на железе

Дисплей, AHT20 (контакт ненадёжный), датчик почвы A0 (сухо ≈ 4095, вода ≈ 1100–1200) и D0,
микрофон и хлопки, питание реле.

## 2. Железо (только то, что важно для кода)

### Распиновка — не менять без явной задачи

| Модуль | Вывод | ESP32-S3 |
|---|---|---|
| Микрофон MAX9814 | Out | GPIO 1 (ADC1) |
| | Gain | 3V3 (40 дБ) · AR — не подключён |
| Датчик почвы | D0 / A0 | GPIO 2 / GPIO 4 (ADC1) |
| Реле | IN | GPIO 5 |
| AHT20 | SDA / SCL | GPIO 8 / 9 |
| Дисплей ST7735S | CS / MOSI / SCK / DC / RST | GPIO 10 / 11 / 12 / 13 / 14 |
| Усилитель MAX98357A (план) | BCLK / LRC / DIN | **уточнить у человека** (кандидаты: 6, 7 + один пин нижнего ряда) |

### Грабли

- **Нижний ряд пинов (15, 16 и др.) плохо контактирует с макетом** — не использовать без подтверждения человеком.
- Не использовать strapping-пины 0, 3, 45, 46 и USB 19, 20.
- Аналоговое — только ADC1 (GPIO 1–10): ADC2 не работает с Wi-Fi.
- **Все обращения к АЦП — под `adcMutex`** (микрофон и почва читаются с разных ядер; без мьютекса — мусор 0/4095).
- Дисплей: `Panel_ST7735S`, `memory_width=128`, `memory_height=160`, `setRotation(3)`.
- На дисплее только латиница (нет кириллического шрифта).
- `RELAY_ON LOW`; D0: `HIGH = сухо`.
- Хлопок: уровень > 2000, длительность < 150 мс.
- Динамик 8 Ом / 0.5 Вт — только через MAX98357A, не напрямую к GPIO. Громкость ограничить (~50 %).

### Зависимости от железа (докупает человек)

- MAX98357A — без него нет голоса (этапы V3+). До его появления код звука собирается, но выключен флагом.
- Отдельное питание насоса — без него «полив» = щелчок реле.

## 3. Архитектура

```
┌──────────────── Устройство (ESP32-S3) ────────────────┐
│ датчики → фильтрация → локальный автополив (резерв)    │
│ микрофон: хлопки + запись фразы 16 кГц                 │
│ дисплей · реле · MAX98357A (I2S)                       │
└──────┬───────────────────────────────┬────────────────┘
       │ HTTP JSON, каждые 30 с        │ HTTP: аудио фразы → аудио ответа
┌──────▼───────────────────────────────▼────────────────┐
│ Сервис (Docker, облачный сервер)                       │
│  api/        телеметрия, события, команды              │
│  ml/         обучение · оценка · реестр · прогноз      │
│  decision/   политика полива + слой безопасности       │
│  voice/      STT (faster-whisper) → LLM → TTS (Silero) │
│  llm/        провайдеры: GigaChat | OpenAI-совместимые │
│  web/        дашборд, чат, калибровка                  │
│  SQLite (том /data)                                    │
└────────────────────────────────────────────────────────┘
```

Принципы:
1. **Устройство автономно.** Без сервера поливает по порогу.
2. **Безопасность полива — в коде** (раздел 5). Ни ML, ни LLM не управляют реле напрямую.
3. **Голосовой помощник не может обойти слой безопасности**: «Джарвис, полей» = запрос, который проходит те же проверки.
4. Устройство только **опрашивает** сервер; входящих подключений к устройству нет (кроме режима настройки).

## 4. Контракты

### 4.1 `POST /api/telemetry` — существующий, не ломать

Запрос:
```json
{"device":"plant1","temp":24.5,"air_hum":55.2,"soil_raw":2500,"soil_pct":50,"soil_ok":true,"soil_dry":false}
```
Ответ — **компактный JSON без пробелов** (прошивка ищет подстроки):
```json
{"command":"none"}
{"command":"water","seconds":3,"dry":3900,"wet":1300}
```
Новые поля добавлять можно; переименовывать и менять формат существующих — нет, пока прошивка не переведена на ArduinoJson (задача F2).

### 4.2 `POST /api/event`
```json
{"device":"plant1","type":"water","value":3.0,"note":"auto"}
```
Причины полива в `note`: `auto`, `auto-D0`, `claps`, `web`, `manual`, `voice`, `ml`.

### 4.3 `POST /api/voice` — новый (этап V2)

- Запрос: `Content-Type: audio/L16; rate=16000; channels=1` (сырые 16-бит PCM, little-endian), заголовок `X-Device`.
- Ответ: `audio/L16; rate=16000` — PCM для воспроизведения + заголовки
  `X-Transcript` и `X-Answer` (URL-encoded) для отладки и показа на экране.
- Ограничения: фраза ≤ 8 с; ответ ≤ 20 с аудио; таймаут обработки 20 с.

### 4.4 Авторизация

- Устройство: заголовок `X-Api-Key` (переменная `PLANT_TOKEN`). **На облачном сервере обязательно.**
- Веб-интерфейс: HTTP Basic (переменные `PLANT_WEB_USER`, `PLANT_WEB_PASSWORD`). **Обязательно** — сервер доступен из интернета.
- Секреты (ключ GigaChat и др.) — только в переменных окружения / `.env`, не в репозитории.

### 4.5 БД (SQLite, том `/data`)

- `measurements(id, ts, device, temp, air_hum, soil_raw, soil_pct, soil_ok, soil_dry_d0)`
- `events(id, ts, device, type, value, note)`
- `calibration(device PK, dry_raw, wet_raw, updated)`
- новые: `voice_log(id, ts, device, transcript, answer, ms_stt, ms_llm, ms_tts)`,
  `models(id, task, version, created, metrics_json, is_champion)`, `decisions(id, ts, device, mode, action, seconds, reason)`

`ts` — время сервера. `soil_raw` хранится всегда (для пересчёта после перекалибровки).

## 5. Безопасность полива (обязательно, покрыто тестами)

| Правило | Значение |
|---|---|
| Максимум одного полива | 10 с |
| Минимальный интервал между поливами по решению сервера / голосу | 30 мин |
| Максимум поливов в сутки | 6 (настройка) |
| Не поливать, если почва влажнее | 70 % |
| Нет свежих данных (> 2 мин) | решений не принимать |
| Устройство без связи с сервером > 10 мин | локальный порог |

Демо-режим (D1) может уменьшить интервалы, но только явным флагом и с пометкой на экране.

## 9. Правила для агентов (копия → AGENTS.md и CLAUDE.md)

1. Нет доступа к железу. Прошивка обязана собираться в CI. В PR — «Ручная проверка».
2. Эталон — текущая прошивка. Поведение сохранять; рефакторинг — малыми шагами.
3. Распиновку не менять; не использовать GPIO 0, 3, 15, 16, 19, 20, 45, 46 без подтверждения человека.
4. Все `analogRead`/АЦП — под `adcMutex`.
5. Контракты раздела 4 не ломать; новые поля — только с обратной совместимостью.
6. Лимиты раздела 5 не ослаблять; любое их изменение — с тестами и пометкой в PR.
